# Upload practice replays

The corpus, its index and what its checks prove are described in `replays/README.md`; read it first. Follow AGENTS.md for the issue, branch, handoff and merge. The goal of a run: every new export is either in the corpus, replaying legally under the current rules, or reported to Mendon with the reason it is not.

## Steps

1. **Find the new exports.** The client writes `practice-<UTC>.json` to its user data folder: on Windows `%APPDATA%\Godot\app_userdata\L5R · Emperor\`, on macOS `~/Library/Application Support/Godot/app_userdata/L5R · Emperor/`, or wherever Mendon says he put them. New means named in neither `games` nor `retired` of `replays/index.json`. Done when you can list each new file with its date; if there are none, say so and stop.
2. **Open the task.** One issue per upload ("Replays: N practice games from <first>–<last date>"), branch `claude/<issue>-practice-replays` (Codex: `codex/...`) from current `origin/main`.
3. **Copy, never edit.** Copy each new export into `replays/games/` byte for byte under its exported name. A replay is evidence of a game: its content is never changed, trimmed or reformatted. One exception: Windows exports are written with CRLF line endings and `.gitattributes` stores replays as LF, so stage the copies, delete each and `git checkout` it to get the stored bytes before indexing; the index must hash the committed bytes.
4. **Prove the files plain.** `python3 tools/replays/check_replays.py`. Before indexing, "not in replays/index.json" is expected for each new file; every other finding is a file that stays out: remove it from `replays/games/` and tell Mendon which file and what the finding was (a path, an address or a link in a string means personal data, so the file is never committed).
5. **Index and replay.** From the repository root: `bash -c 'source tools/env.sh && dotnet run -c Release --project tools/ReplayCheck -- --write-index'`, then the same without `--write-index`. Done when it ends "every card and every move legal".
6. **Retire what the rules refuse.** A refused game names its command and the engine's reason. Remove the file from `replays/games/`, delete its entry from `games`, and add `{"file", "sha256", "reason"}` to `retired`: the command number, the reason, and, when you can find it, the rules change that made it illegal (`git log --merges --since=<game date>` on `src/L5R.Core`, with merge times against the export's UTC timestamp). Run step 5 again until it is clean.
7. **Notes.** Ask Mendon once, listing the new games (date, his stronghold, the bot's stronghold, result), for a note on any of them: the bot level, a deck experiment, a known misplay. Write what he gives into each entry's `note`; leave the rest empty and carry on.
8. **Plays by Stronghold.** `bash -c 'source tools/env.sh && dotnet run -c Release --project tools/ReplayCheck -- --decks'` prints one row for every Stronghold in the game, grouped by clan: the bot-pool decks that play it, games Mendon played with it (won), games the bot played with it at Hard against him (bot won), games at other levels, and **Needed for bot training**; then a clan summary (Strongholds, with a pool deck, at both targets). The targets per Stronghold the pool plays are 5 games played by Mendon (a Stronghold-specific habit becomes a rule only after it shows in 3 separate games) and 10 played by the bot at Hard (if the bot loses all 10, its win rate against him is under 26% at 95% confidence, the fewest games that can show it is not yet challenging); `tools/ReplayCheck/DeckTable.cs` gives the reasoning. A Stronghold without a pool deck reads "no pool deck yet"; a clan is ready for clan-wide heuristics when every Stronghold in it has a pool deck at both targets. Put both tables in the PR, and always give them in the report, whole, every upload.
9. **Share.** Both checks again, then handoff, audit, commit `replays/games/` and `replays/index.json` together, push and open the PR: games added, games retired with their reasons, stage 1 and stage 2 output, the plays-by-Stronghold tables. A replay-only PR runs the two replay checks and the policy checks, not the desktop matrix.
10. **Merge.** When every check on the PR has passed (read the list; a failure or a pending check means wait or fix), and no `nightly-broken` issue is open, merge under Mendon's standing authority. Done when the PR is merged and the report to Mendon names the games added, the games retired and why, the corpus total and the plays-by-Stronghold tables (both, in full), with the pool Strongholds that most need games named first.
